# Muhasebi — notes for AI assistants

SaaS for mobile-phone parts/accessories/repair shops in Egypt. Product plan: `PLAN.md`. Technical plan: `TECH_PLAN.md`. UI copy is Egyptian Arabic, RTL.

## Layout
- `apps/api` — Laravel 13, PHP 8.4, PostgreSQL. Modular monolith under `app/Modules/*`, shared kernel in `app/Support/*`.
- `apps/web` — Nuxt 4 SPA (`ssr: false`), Nuxt UI 4, Pinia. Talks to `/api/v1` with a Sanctum bearer token.

## Rules that tests enforce (`apps/api/tests/Architecture`)
- A module may only reference another module's `Contracts\` and `Events\` namespaces.
- Every model under `app/Modules/*/Models` uses `BelongsToTenant` (one shop) or `SharedBetweenTenants` (rows owned by two shops, e.g. inter-shop orders), except the allowlist (Tenant, User).
- Every route of an `Optional` module carries `module:{key}` middleware.
- Every signed-in API route checks a permission: `can:` middleware, a Form Request with its own `authorize()`, or an `abort_unless(...->can(...))` in the action (`RouteAuthorizationTest`; the few exceptions are listed there).

## Conventions
- New module: create `app/Modules/{Name}/module.php` returning a `ModuleManifest`; routes in `routes.php` (auto-prefixed `/api/v1`), migrations in `Database/migrations`, listeners registered via a `ModuleServiceProvider` `$listen` array.
- Cross-module side effects: if it must succeed with the change → call a `Contracts\` interface inside the transaction; otherwise → `EventRecorder::record(new SomethingHappened(...))` and a `ModuleListener` elsewhere.
- Permissions are declared in module manifests (`permissions: ['key' => 'Arabic label']`) and enforced with `can:{key}` route middleware / `$user->can()`. Owners have every permission of the modules the shop can use; others get their role's permissions ∩ usable modules (`Identity\PermissionResolver`). Owner-only screens use the `owner` gate.
- Routes that act inside a branch add the `branch` middleware and read `Support\Tenancy\CurrentBranch` (from the `X-Branch-Id` header).
- Sensitive actions call `Support\Audit\Auditor::record()` inside their transaction (shows in سجل العمليات).
- Controllers are thin: Form Request → Action → API Resource. Business rule failures throw `DomainRuleException` (rendered as `{message, code}`).
- Money is stored as integer piasters. IDs for shop data are UUIDv7 (`HasUuids`).
- Don't cache Eloquent models (Laravel 13 cache refuses to unserialize objects); cache arrays.
- Other shops' public info (name, code, phone) comes from `Identity\Contracts\ShopDirectory`, never from Identity's models.
- UI follows design direction A (`docs/design/option-a-*.png`): theme tokens in `apps/web/app/assets/css/main.css`. Dates/numbers use Latin digits (`ar-EG-u-nu-latn`, `.num`).
- Catalog: what is sold/stocked is a `ProductVariant` (own barcode, prices in piasters); compatibility (`device_model_product`) is per product. Text search goes through `Support\Text\SearchText` (Arabic normalisation: أإآ→ا، ة→ه، ى→ي) against stored `search_name` columns with `pg_trgm` indexes; `Product::search()` ANDs the words across name, SKU, barcode, brand and compatible models. New shops get `DefaultCatalog` via `TenantRegistered`. Every selling-price change writes the append-only `price_changes` (`Catalog\Support\PriceHistory`, from the product form or a bulk edit); bulk edits (`/products/prices`, `BulkPriceAction` + `PriceRule`: percent / amount / fixed price from a price field or the branch's average cost, rounding) preview first, then apply with an audit entry.
- Stock: only through `Inventory\Contracts\StockLedger` (`receive` = new lot + weighted `avg_cost`; `issue` = FIFO over lots, may go negative and is then costed at `avg_cost`), called inside the caller's transaction. `stock_movements` is append-only; `stock_levels`/`stock_lots` are balances locked per (branch, variant). Stock is per branch (`branch` middleware). Other modules read variants via `Catalog\Contracts\VariantCatalog`, never Catalog models. Costs are shown only with `products.view_cost`. IMEI / serials (products with `track_serial`): `Inventory\Contracts\SerialRegistry` (`receive` / `issue` / `takeBack`, next to the StockLedger call with the same `StockReference`; `serial_numbers` = where each unit is now, append-only `serial_events`); a line needs one serial per unit (`SerialCount::check`) on purchases, sales and their returns, stored on the line's `serials` and printed on the receipt. A serial never received (opening stock, older stock) is registered as it's sold. Adjustments and counts (`AdjustStockAction`) need the serials of the difference (the extra units received, the missing ones issued); opening stock takes them optionally (one per unit when given); repair parts need theirs (`repair_ticket_parts.serials`, issued as `RepairUse`, `takeBack` on removal). The web asks with `InventorySerialsInput` wherever the row / price-check item has `track_serial`. Lookup `GET /inventory/serials?q=` (`/inventory/serials`); the POS adds a unit by scanning its IMEI.
- Purchases (Suppliers module): `CreatePurchaseAction` receives each line into stock at its cost after the invoice discount and posts the total to the supplier account; `SupplierAccount::post()` keeps `suppliers.balance` (> 0 = the shop owes) and the append-only `supplier_transactions` in step under a row lock. What is paid now (and `/suppliers/{id}/payments`) comes out of the user's shift drawer via `CashDrawer` (`DrawerEntry::SupplierPayment`, negative amount; bank transfers never, `from_drawer: false` for money from the safe). Returns issue from the purchase's own lot (`StockLedger::issue(..., fromLotId:)`). Per-shop document numbers come from `Support\Numbering\DocumentNumbers` inside the creating transaction. Ledgers order by their `seq` identity column, never by timestamps.
- Sales (POS): `CompleteSaleAction` prices lines from the catalog (`VariantSummary::priceFor(level)`), issues stock FIFO and stores each line's `unit_cost`; the client sends the sale `id` (the cart id) so a retried checkout is saved once. Only cash gives change. Returns refund each unit's share after the invoice discount and restock sound units at the line's cost. Receipts have a `public_token` → public page `/r/{token}` (QR on the receipt, WhatsApp share); pages opt out of login with `definePageMeta({ public: true })`.
- Offline POS: the cashier is never blocked by the internet. `public/sw.js` (registered by `plugins/pwa.client.ts`, production builds only; the build writes its version + `/_nuxt` precache list via the `nitro:build:public-assets` hook) serves the app shell offline and never touches `/api`. `useConnectivity()` = navigator.onLine AND the API answering (`useApi` marks it; `/up` probed while down); `withOfflineCache()` keeps the last session / POS options / open shift in localStorage. The POS keeps the branch catalog in IndexedDB (`utils/idb.ts`, `usePosCatalog` ← `GET /pos/catalog?page=`, 500 per page, stock and in-stock serials here) and searches it with `normalizeSearch()` (same folding as `SearchText`). A checkout with no answer goes to the outbox (`useOutbox`: exact body + `offline: true` + `sold_at`, receipt marked «لسه ما اتسجلتش…», no QR/link, no آجل), sent in order by the user who made it on reconnect / focus / every 30s (4xx → «فواتير مستنية» panel to retry or discard; 5xx/no answer → back-off). The API stores `sold_at` (only with `offline`, ≤ 5 min ahead, ≤ 7 days old) as `completed_at`; an offline line's `unit_price` (what the POS charged) is kept when it was a real price of the variant in the last week (`VariantCatalog::pricesSince`, from `price_changes`), with a `sales.offline_price` audit entry; the sale id keeps a resend saved once. A shift can't be closed from the web while its cashier's outbox for that branch isn't empty.
- Installable app (PWA): `public/site.webmanifest` (ar/rtl, `start_url /?source=pwa`, standalone + window-controls-overlay, shortcuts بيع جديد / استلام جهاز / استعلام سعر `/?action=price-check` / الوردية, narrow + wide `screenshots/`), icons in `public/icons` + `favicon.*` + `apple-touch-icon.png` drawn by `scripts/pwa-icons.mjs` (bump `?v=` when they change). `plugins/pwa.client.ts`: registers the SW; a newer worker waits (no auto `skipWaiting`) → toast «فيه نسخة جديدة — حدّث» → `SKIP_WAITING` + reload; theme-color metas = `--ui-bg` (device light/dark, or the picked theme); first launch from `?source=pwa` reopens the last route (`muhasebi:last-route`); `launchQueue` (focus-existing) routes shortcuts; installed, off-site links open in the browser. «نزّل التطبيق» = `useInstallApp()` (`beforeinstallprompt` kept early by an inline head script; iPhone/iPad and Safari/Firefox get `InstallSteps` instead) in the user menu, Ctrl+K, the dismissible home `InstallCard` (per device) and `/settings/app`; all hidden when running installed. Standalone CSS in `main.css`: safe-area insets (`viewport-fit=cover`, `.app-titlebar` / `.app-main` / `.app-sidebar`, `--app-topbar-h`), WCO drag region, no overscroll installed and on the POS (`app-no-overscroll`). Caddy: manifest `application/manifest+json` no-cache, icons/screenshots a year. Play Store via TWA: notes in `docs/DEPLOY.md`.
- Supplier returns (SupplierReturns, optional; `/supplier-returns`): the returns bin («سلة المرتجعات») is `supplier_return_items` rows (per branch; one per unit for serial-tracked; lot, cost, source, fixed `Contracts\ReturnReason`, origin) holding units OUT of sellable stock. In: `AddToBinAction::fromStock` (inventory «طلّع للمرتجعات»: `StockLedger::issue` as `MovementType::ReturnsBin`, serials `SerialRegistry::setAside` → damaged) or `fromDocument` (no stock move: `SaleRefunded::$damaged` — a not-restocked sale-return line with optional `defect_reason` — and `Repairs\Events\DefectivePartRemoved` from `DELETE …/parts/{id}?defective=1`, via ModuleListeners, so only when the module is usable). Source (`Support\SourceDetector`): serial (`SerialRegistry::origins` → purchase via `Suppliers\Contracts\SupplierAccounts`, a replacement → its note, or an IMEI on a received goods order via `ShopOrders\Contracts\PartnerPurchases`), else the lot it left (`StockLedger::issuedFor` / `lotOrigins`), else the employee picks (`GET /supplier-returns/sources`: recent purchases of the variant first). The sorting screen groups the bin by source; selected lines → one note per source (`SRN-00001`, `DocumentNumbers`), A4 `SupplierReturnsNotePrint`, WhatsApp template `supplier_return_note`. Note: pending → sent → settled per line (`accepted_qty`): accepted = credit (`SupplierAccounts::creditReturn`, `return_note` on the statement) / refund (`refundReturn` + `CashDrawer` `DrawerEntry::SupplierRefund`, not for bank transfer) / replacement (`receive` as `SupplierReplacement`, new serials); refused = back into the lot it left (`StockLedger::restore`, `ReturnsBinBack`, `putBack`) or written off (`release`, audited); or cancelled back to the bin. Partner-shop sources only record this shop's side (`Events\ReturnNoteSettled` is the hook). Reports: `supplier_return_rate`, `supplier_returns_open` (by age); the sales report's profit adds «تعويض مرتجعات الموردين» (accepted value of notes settled as credit / refund in the period). Costs only with `products.view_cost`.
- Cash (Cash module): selling needs the cashier's open shift (`cash_shifts`, one open per user per branch). Money moves only through `Cash\Contracts\CashDrawer::record()` inside the caller's transaction (cash always needs an open shift; card/wallet join one if open); `cash_movements` is append-only. Expenses / deposits / withdrawals are cash on the user's shift; closing stores expected vs counted per method. Shift numbers `SH-00001`.
- Customers: `customers.balance` (> 0 = owes the shop) and the append-only `customer_transactions` move together under a row lock (`CustomerLedger`). Credit (آجل) is the `credit` sale payment method: needs a customer and `customers.credit`, respects `credit_limit` via `Customers\Contracts\CustomerAccounts::chargeSale()`; a return with `refund_method: credit` goes back to the account. Phones are stored E.164; show them with `localPhone()`.
- Customer privacy (Law 151/2020): consent to keeping their data is recorded on the customer (`data_consent` true/false/null = never asked, `_at`, `_by_name`) from the pre-ticked `CustomersConsentCheckbox` on the customer form (POS picker too) and repair intake (`consent` → `CustomerAccounts::findOrCreate`). Erasure (`POST /customers/{id}/erase`, owner; `EraseCustomerAction`) refuses a non-zero balance or open tickets, then anonymises: name «عميل محذوف» (`Support\Privacy\Anonymised`), no phone/notes, inactive, `erased_at`; the drawer notes (`CashDrawer::redactNotes`) and audit descriptions (`Auditor::redact`) lose the name in the transaction; `Customers\Events\CustomerErased` (a keyed `PhoneFingerprint`, never the number) lets each module anonymise its copies (Sales, Repairs incl. unlock code and IMEI, Messaging) with listeners that set `evenWhenModuleDisabled()`. A module holding a customer's name/phone must add such a listener. Export (`GET /customers/{id}/export`, customers.manage) is JSON from `Sales\Contracts\CustomerSales` / `Repairs\Contracts\CustomerRepairs`. Retention: `customer_privacy_settings.retention_years` (owner, 1–10, off by default) and the daily `customers:erase-inactive` go through the same action. Public notice: `/privacy`.
- Repairs: a `RepairTicket` (per branch, `RP-00001`) goes received → diagnosing → awaiting_approval → repairing → awaiting_part → ready / rejected (`TicketStatus::next()`), then `DeliverTicketAction` settles it (change from cash only; credit via `CustomerAccounts::chargeRepair`; a deposit larger than the bill is refunded) and starts the warranty. Every change writes the append-only timeline (`Support\Timeline`). Money goes through `Support\TicketMoney` → `CashDrawer` (`DrawerEntry::Repair`); parts leave stock with `MovementType::RepairUse` and come back with `RepairReturn`. Faults are snapshots of the shop's editable lists. The unlock code is encrypted and only returned with `repairs.update_status`. Public tracking: `/t/{token}` (API `public/repairs/{token}` resolves the shop via `ResolveTicketShop`). WhatsApp text per status: the `repair_{status}` message template. Technician commission: per-technician `CommissionRule` (percent of labor-after-discount or of profit, or fixed per device), fixed on the ticket at delivery (`Support\Commission`; none for warranty returns); shown to that technician and to `reports.profit`. The repairs report (`Reports\Definitions\RepairsReport`) groups by technician, fault or model.
- Messaging: WhatsApp texts are templates (`Messaging\Support\Templates`: key, variables, built-in wording; the shop's rewording in `message_templates`, edited at `/settings/templates` with `messages.templates`). The web fills them with `useMessages()` (`renderTemplate`: `{name}` → value, a line whose variable is empty is dropped) and every send is logged in the append-only `message_logs` (`POST /messages/log`, `messages.send`). Other modules ask `Messaging\Contracts\MessageHistory::lastSent()`; repairs uses it for ready devices whose customer wasn't told (`ready_notified_at`, summary `unnotified`).
- Used devices (المستعمل, optional `used_devices`): `BuyDeviceAction` (multipart `POST /used-devices`, branch) records the seller once per national ID (`used_device_sellers`: ID `encrypted` + keyed `national_id_hash`; `Support\NationalId` checks century 2/3, birth date, governorate and derives birth date/gender), the card photos (+ ≤ 4 device photos, ≤ 5 MB, shrunk by the web first) encrypted on the local disk (`PhotoStore`, served by `GET /used-devices/{id}/photos/{photo}`; card photos need `used_devices.view_seller` and every view is audited), the IMEI (Luhn, `Support\Imei`; one in stock refused, history from `SerialRegistry::history()`), grade A/B/C + `Checklist` (iCloud/Google removed must be yes); each device becomes its own variant of «{model} مستعمل» (`Catalog\Contracts\UsedDeviceCatalog::addUnit`, track_serial, asking price; price edits via `setUnitPrice` → price history), received with `MovementType::UsedPurchase` + its IMEI, cash paid through `DrawerEntry::UsedDevicePurchase` (wallet/InstaPay/bank never touch the drawer). It sells at the POS by IMEI like any serial; `SyncSoldDevices` (on `SaleCompleted`/`SaleRefunded`, `Sales\Contracts\UnitSales`) marks it sold with its net sale price (profit = that − purchase price) and deactivates the variant, or back in stock on a return. Seller data only with `used_devices.view_seller` (owner, managers); purchase price/profit with `products.view_cost`. Sellers under 18 are refused (`seller_under_age`, `BuyDeviceAction::MIN_SELLER_AGE`). Privacy: erasing a seller (owner, or `EraseSellerWithCustomer` on `CustomerErased` by phone fingerprint) drops name/phone at once; for EVERY seller the national ID and card photos are kept `used_device_settings.id_retention_years` (default 3) after their last sale, then the daily `used-devices:purge-ids` deletes them. Screens `/used-devices` (list, `new`, `[id]` with the A4 «إقرار بيع جهاز» `UsedDevicesDeclaration`, `sellers`); report `UsedDevicesReport` (by device / model / grade, stock age).
- Installments (التقسيط, optional `installments`; `/installments`): an `InstallmentPlan` (`INS-00001`, shop-wide, made in a branch) splits what a customer ALREADY owes — a credit sale's آجل (`Sales\Contracts\CustomerSales::creditOf`) or their account outside other active plans (`PlanBook::outstandingFor`) — into `installment_items` (`Support\Schedule`: equal, rounded down to whole pounds, the last takes the rest; every 1–3 months; mirrored by `installmentSchedule()` in `utils/installments.ts`). Its markup goes on the account (`CustomerAccounts::chargeInstallmentMarkup`, type `installment_markup`) and counts as profit in the sales report («فوايد التقسيط»). Collecting on a plan = `CustomerAccounts::collect(..., source: 'installments')` (the customer «تحصيل»: ledger + `CashDrawer` + audit) then `PlanBook::apply` (oldest installment first, append-only `installment_payments`, completes the plan); a payment from the customer page reaches plans via `ApplyAccountPayments` (on `CustomerPaid` with no source) only for the part the ordinary آجل no longer covers. Cancel = the rest stays ordinary آجل. `GET /installments/due` (late / today / week / month), `available`, summary; A4 «اتفاق تقسيط» `InstallmentsPlanPrint`; WhatsApp `installment_reminder`; POS receipt «قسّط الآجل», customer page tab + «قسّط الحساب». Switches: suggested markup (% a month), guarantor required, reminders. `installments.manage` (make / cancel; managers) and `installments.collect` (cashiers too). Report `InstallmentsReport` (new plans / who's late). `AnonymiseInstallmentCustomers` on erasure.
- Partner repairs: a ticket can go to a partner shop (`OutsourceTicketAction` → `ShopOrders\Contracts\PartnerRepairs::send`, a `repair` shop order; `outsourced_*` on the ticket, can't be delivered until the partner hands it back, the partner's price is `outsource_cost`, counted in profit and commission via `RepairTicket::cost()`). `Repairs\Listeners\SyncPartnerRepairs` on `ShopOrderUpdated`: the sender's ticket follows the order; the partner accepting opens a ticket per device (`partner_order_id`, the sending shop as customer, main branch), and `Support\PartnerSync` moves the order (preparing / ready / delivered with each device's bill as its price) as those tickets move. Repairs is shown to accessories and phone shops too (`trialFor: ['repair']`: only repair shops start on it).
- Services (الشحن والتحويلات, optional): per-branch `service_accounts` (wallet: Vodafone Cash / e& / Orange / WE Pay / InstaPay; airtime: رصيد) whose `balance` and `cost_value` (what the balance cost: airtime is bought at a distributor discount) move only through `Services\Support\ServiceLedger` under a row lock, in step with the append-only `service_transactions` (`seq`, numbers `SV-00001`, `fee` / `profit` / `cash` stored per row). Counter operations (`RecordOperationAction`): deposit = drawer +amount+fee, wallet −amount; withdraw = wallet +amount, drawer −(amount−fee) or, in the account's `wallet` fee mode, wallet +amount+fee, drawer −amount; top-up = drawer +face+fee, airtime −face, profit = fee + the face's discount. Fund / cash-out (`MoveAccountMoneyAction`, `services.fund`) go from/to the drawer or the safe (no drawer row). Cash goes through `CashDrawer` (`DrawerEntry::Service`), so every operation needs the open shift and shows on the close. Mistakes = a reversal row (`reverses_id`, every amount negated; own slip same day with `services.manage`, any with `services.settings`), never an edit. Fee rules per account + operation (`FeeRule`: percent in basis points, fixed, min/max, round up; mirrored by `serviceFee()` in `utils/services.ts`); a fee other than the suggested one needs `services.fees`. Daily limit only warns (`meta.warning`). Customer phone/name on a row are anonymised by `AnonymiseCustomerServices`. Screens `/services` (counter: Alt+1…9 account, Alt+D/S/T operation, Enter saves, 80mm `ServicesReceipt`), `/services/transactions`, `/services/accounts`; report `ServicesReport` (by account / operation / day, profit with reports.profit); `/sales/stats` `services` = today's / the period's services profit, apart from goods, via `Services\Contracts\ServiceProfits`.
- Notifications (core module, the top-bar bell `NotificationBell`): one `notifications` row per shop (title, body, icon, `to` web link, optional `permission` — only users who `can()` it see it) and per-user read marks in `notification_reads`. Own-account routes `GET/PUT /notifications/preferences`, `GET /push/key`, `POST/DELETE /push/subscriptions`, `POST /push/test`. Web: `usePush()` (iOS needs the installed app; logout drops this device), `/settings/notifications` (user menu), `sw.js` shows pushes and opens their `url`.
- Owner app (`owner_app`, optional; phase A of `docs/plans/online-store-and-owner-app.md`): `owner_app.alerts` (owner, managers) receives `Notifications\Listeners\NotifyOwner` — `Cash\Events\ShiftClosed` with |difference| ≥ `owner_app.cash_alert` (ج, default 50) and every `SaleRefunded` (`owner_app.refund_alert`) — and the daily summary: `notifications:daily-summary` (every 10 min) sends once per Cairo day (`daily_summaries_sent`) after `owner_app.daily_summary`'s hour (default 23) the lines of `Reports\Contracts\DailySummary` (the sales report for the day, all branches). Phase B: `/owner` (menu «النهارده (المالك)», quick action) = `GET /owner/today` (`Reports\Owner\OwnerToday`: today so far vs the same time yesterday, by hour, returns, expenses, open drawers with expected cash, top items, low stock, repairs / installments waiting; cached 30 s; profit with reports.profit) and `GET /owner/feed?kinds[]=&before=` (`Reports\Owner\OwnerFeed`: a union of sales, returns, drawer expenses / withdrawals / deposits, shifts opened / closed, retail price changes, newest first, 25 a page); routes `module:owner_app` + `can:owner_app.alerts`, branch filter limited to `BranchDirectory::accessibleBranches`. - Approvals (phase C, `OwnerApp\Contracts\Approvals`): switches `owner_app.approve_discount` (% above), `approve_below_cost`, `approve_return` / `approve_withdrawal` (ج above), `approve_credit_limit` (آجل past the customer's limit: approved = `chargeSale(..., overLimitApproved: true)` instead of `credit_limit_exceeded`), all off by default. Otherwise 409 `approval_required` with `approval.token` (signed, `Support\ApprovalToken`, 30 min); the web (`useApproval().ask()` → `ApprovalsRequestModal`) sends it to the approvers (`POST /approvals` → `approval_requests`, 10 min, urgent push `approval.requested` + Reverb) and waits, or takes a manager's PIN (`POST /approvals/pin`, `StaffDirectory::matchPin`), then retries the same request with `X-Approval-Id`: approved, unused, unexpired, same requester, same payload hash — used once. PIN: `account/pin` (password, 4–6 digits) on `/settings/security` (`SecurityPinCard`, every user: it also unlocks the app).
- App lock («قفل التطبيق», per device, `SecurityAppLockCard` on `/settings/security`): `useAppLock()` keeps `{enabled, passkey}` in localStorage per user; the app opens locked and locks after 5 min hidden (`SecurityLockScreen` in the layout); `POST /account/unlock` with the PIN or a passkey assertion marks this token verified for `AppUnlock::MINUTES` (5) — 5 wrong tries in a row delete the token (401 `unlock_locked_out`). Offline the app still opens (never blocks the cashier): the PIN against a PBKDF2 hash kept from the last online unlock (`muhasebi:app-lock-pin:{user}`), or this device's passkey checked locally; `confirm()` always needs the API. Passkeys (`passkeys` table, `account/passkeys` + `/options` with the password): `Support\Security\WebAuthn` checks client data (type, challenge from cache, origin in `services.webauthn.origins`), authenticator data (rpId hash, user present + verified, counter) and the ES256 / RS256 signature with openssl; the browser sends the SPKI key from `getPublicKey()` (no CBOR; `utils/webauthn.ts`). Google Play (TWA): `/.well-known/assetlinks.json` from `TWA_PACKAGE` / `TWA_SHA256` (web route, Caddy proxies it).

## Deployment
- `infra/production/`: Docker Compose stack (Caddy edge with auto-HTTPS serving the Nuxt static build and proxying `/api` to FrankenPHP; Horizon worker, scheduler, Reverb, Postgres 17, Redis). `init.sh` once, `deploy.sh` per update, `backup.sh`/`restore.sh`. Guide: `docs/DEPLOY.md`. On a server whose nginx already owns 80/443, `COMPOSE_FILE=compose.yml:compose.nginx.yml` (set by `./init.sh <domain> <email> nginx`) binds Caddy to `127.0.0.1:8088` over plain HTTP and trusts nginx's `X-Forwarded-*`; `nginx-site.conf` is the matching nginx site.
- `setup-admin.sh` (interactive, re-runnable) sets up the admin panel on a server: asks domain / allowed IPs / InstaPay / admin email + password, writes `.env` (backup copy), adds the nginx site + certbot in nginx mode, deploys, runs `billing:admin --password-stdin` and `billing:admin-2fa`, then checks the panel answers.
- Backups: the `backup` compose service (`Dockerfile.backup`: postgres:17-alpine + rclone; `backup/schedule.sh` → `backup/dump.sh`; the api's `storage` volume mounted read-only at `/storage`) dumps the database and archives `storage/app` (`-files.tar.gz`, same timestamp; `BACKUP_FILES=0` = database only) daily at `BACKUP_TIME` (`BACKUP_TZ`) into `infra/production/backups/`, keeps `BACKUP_KEEP_DAYS` (14), copies to `BACKUP_RCLONE_REMOTE` when set (rclone env config `RCLONE_CONFIG_*` in `.env`), and is unhealthy when the last good dump is > 25 h old. `deploy.sh` takes one before migrations (`SKIP_BACKUP=1` skips); `backup.sh` = one now; `restore.sh` stops the service while it restores (the matching files archive too, extracted over the current files). Keep scripts shellcheck-clean (CI runs it).
- CD: the `deploy` job in `.github/workflows/ci.yml` runs after api/web/docker pass on `main`, SSHes with a key pinned (`restrict,command=`) to `infra/production/ci-deploy.sh`, which only accepts `deploy <sha>` for a commit on `origin/main`, checks it out, runs `deploy.sh` and waits for the API healthcheck.
